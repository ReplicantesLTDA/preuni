# Internal Bridge Contract: Go monolith ↔ correction service

Not an HTTP contract — see research.md §1. The bridge is the shared-Postgres
`correction.correction_jobs` table. This document is the contract for that
table's shape and the access-privilege boundary, since it is the only
interface between the two systems (per data-model.md).

## Table: `correction.correction_jobs`

Go monolith privileges: `INSERT`, `SELECT`. Never `UPDATE`/`DELETE`.
Correction service privileges: full (owns migrations).

| Column | Written by | Read by |
|---|---|---|
| `id`, `user_id`, `essay_text`, `prompt_theme_title`, `prompt_theme_context`, `queued_at` | Go (on insert) | both |
| `status`, `started_at`, `completed_at` | Python worker | Go (poll) |

## Enqueue contract (Go → table)

Go inserts exactly one row per accepted `essay_submissions` row, in the same
transaction (data-model.md, cross-system reconciliation flow step 1).
`status` defaults to `pending`. Go must not retry-insert on timeout without
a uniqueness guard — `id` is generated by Go and reused as the idempotency
key if a retry is needed.

## Result contract (table → Go)

Go polls (or a lightweight subscriber) for rows where
`status IN ('completed', 'failed')` and `essay_submissions.correction_job_id`
matches. On `completed`, the corresponding `correction.corrections` row
(joined by `correction_jobs.id` — exact join key finalized at
implementation time, e.g. `corrections.job_id`) supplies the graded payload
that becomes `essay_grades` (data-model.md). On `failed`, Go reads
`error_code` from that same row and maps it into the `grading_failed`
response shape (see `public-api.md`), reusing the correction service's
existing typed taxonomy (`provider_rate_limited`, `provider_timeout`,
`schema_violation`, `internal_error`, etc. — see
`corretor-redacao/specs/001-enem-correction-api/contracts/error_codes.md`,
which this feature keeps as-is on the Python side).

## Failure handling (spec Edge Cases)

If a `correction_jobs` row never transitions out of `pending` within a
configured grading timeout (value finalized at tasks stage), Go's
reconciliation path marks the `essay_submissions` row `failed` with
`error_code: internal_error` so the user is never left in indefinite
"pending" (spec SC-001) — the underlying `correction_jobs`/`corrections`
rows are left for operator inspection, not deleted.
